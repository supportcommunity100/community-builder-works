# Contributing to Community Builder Works

Thank you for your interest in contributing! We welcome improvements to templates, documentation, and starter workflows.

## How to Contribute

### 1. Fork the Repository
Click the **Fork** button at the top right of the repository page on GitHub to create a copy of this repository under your account.

### 2. Clone Your Fork
Clone your forked repository to your local machine:
```bash
git clone <your-fork-url>
cd community-builder-works
```

### 3. Create a Branch
Create a descriptive branch from `main` for your changes:
```bash
git checkout -b feat/your-feature-name
```
(Use prefixes like `feat/`, `fix/`, or `docs/` to keep branch names organized.)

### 4. Make and Commit Your Changes
Make your edits, test them locally if applicable, and commit with a clear, concise message:
```bash
git add .
git commit -m "Add template for community onboarding"
```

### 5. Push and Open a Pull Request
Push your branch to your fork on GitHub:
```bash
git push origin feat/your-feature-name
```
Then navigate to the original repository and click **New pull request**:
- Provide a clear title and summary of what changed and why.
- Reference any related issue (e.g., `Closes #12`).
- Keep pull requests focused on a single topic or improvement.

## Guidelines for Opening Issues

Before opening a new issue, please search existing issues to avoid duplicates. When creating an issue:
- **Bug reports:** Include a clear title, steps to reproduce, expected behavior, and actual behavior.
- **Feature or template requests:** Describe the use case, proposed structure, and why it benefits the community.
- **Documentation improvements:** Point out the specific file or section that needs clarification.

Thank you for helping improve Community Builder Works!
